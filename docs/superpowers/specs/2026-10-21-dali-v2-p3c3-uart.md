# P3c3b: managed HAT ownership and health

Recovery amendment, 2026-10-22: the owner's
[quiet-period policy](2026-10-22-dali-v2-quiet-recovery.md) replaces general
Boot-only startup/reopen/receive recovery. Known partial-write poison remains
Boot-only and is transferred after actual teardown. The proposed persistent
UART journal was dropped; the older crash/reset prerequisite below is superseded.

Continues the approved architecture from service checkpoint `c0883aa`. This is
UART lifecycle/health integration; the service still refuses fixture operations
until P4 supplies the capability engine. Canonical daemon/process startup follows
in P3c3c. No new user-owned product choice is required.

## Verified boundaries

At checkpoint `c0883aa`, `Serial::open` configured raw 19200/8N1/nonblocking
descriptors using a detached OS thread. Transactions owns the one continuous Monitor and exclusive
capacity-one request slot. Timeout/cancellation after writing preserves Late
state; its eligible late terminal can restore Ready. ResetRequired retains the
monitor until a subsequent Boot rearms it. Version alone is not that barrier.
Transactions close includes monitor close and actor completion; all helpers are
runtime tasks. The managed runtime waits for actual helper/blocking destruction.

The [ATX manual](https://atxled.com/pdf/AL-DALI-HAT-I.pdf), rechecked 2026-10-21,
documents proactive D bus-status observations and B boot records. A D observation
is a snapshot, not proof a particular query caused it. Preserve version strings
and reported channel count; the V variant field has conflicting descriptions,
so do not infer channel capability or repeat policy from it. The manual does not
document a UART command to reset the co-processor. No physical transcript is
available. Reopening a TTY cannot establish that earlier HAT work has ended.

## Chosen shape and files

Keep hardware resources in the same managed service runtime. Add a small owned
HAT lifecycle component under `src/service/hat.rs` (split if useful), integrated
into the service actor's select and snapshots. There is no second UART reader,
protocol implementation or frontend-owned connection. The existing Transactions
actor remains the exclusive command owner.

An independent all-purpose hardware worker with another request queue would add
admission/order ownership without a caller yet; the service-owned lifecycle
component is sufficient. Resource preparation and cleanup use owned abort-on-drop
join handles so the actor can process metadata while those helpers are pending.
Canceling a select branch cannot lose a completed resource/result. P4 will use the
same service operation permit for fixture address resolution/sequences and give
health work lower priority instead of adding a parallel write path.
Unexpected helper panic/death is a service failure, not a silent retry. Preserve
blocking-task panics through owned preparation tasks and report them to the
managed supervisor. Expected serial I/O loss remains a hardware availability
failure with the conservative correlation/reset policy below.
After open completes, the service owns Transactions before launching any
initialization/poll helper. Those helpers return observations/errors; failure
or cancellation cannot drop the service's potentially poisoned session.
An unexplained Closed state without observed transport-loss evidence is a
service failure, since the current Transactions API lacks a detailed exit cause.
Metadata phase updates must retain current hardware facts instead of resetting
the existing Snapshot field to NotStarted.

Touch `src/atx/serial.rs` and its tests, service owner/proxy/snapshot integration,
new lifecycle/tests, wait registry, control table/ledger, service/inventory/support
guides and progress. Legacy binary/modules remain untouched.

## Open, ownership and teardown

Construct optional UART settings without I/O. The embedding constructor defaults
to metadata-only (existing tests/users); a builder supplies a UART/PTY path and
explicit RepeatPolicy. Canonical daemon startup will supply its UART path. Never
embed the emulator in production as an alternative protocol shortcut.

Move serial open/configuration to Tokio spawn_blocking. The runtime must own a
still-running opener after caller expiry/cancellation. A result arriving late
drops its owned fd. An open deadline is terminal for this UART owner: do not
retry and accumulate outstanding openers. Ordinary completed open errors can
retry at a paced interval, with at most one opening/closing helper outstanding.
Runtime destruction remains incomplete while a blocked opener remains alive.

The service becomes available and attaches Reporter independently of UART setup.
Opening/initialization/close cannot block inventory edits or broker-independent
snapshots. Hardware states distinguish NotStarted, Connecting/Initializing,
Ready with observed version/status, unavailable retry, waiting for late response,
and reset required. Saved configuration readiness remains separate.

Close service admission first. Hardware and ConfigStore cleanup share one local
absolute budget within the managed cooperative stop period; parent forced
cancellation and its shared process ceiling remain final. ServiceContext does
not expose that parent deadline. Do not restart helpers during stop. Retained
frontend handles cannot retain resource ownership after actual close. Failed
cleanup takes the incomplete-stop path; never detach a resource owner.

## Correlation and recovery

Hold the same Transactions object across WaitingLateReply/ResetRequired. Do not
drop/reopen it, issue a new probe, or manufacture an initialization epoch to
clear ambiguity. Continue receiving public events/status while requests are
refused. An eligible terminal retires Late through the existing actor. A Boot
permits reinitialization only after the actor reports Uninitialized. No guessed
time delay clears poison.

Late initialization is special: its eligible delayed Version returns the actor
to Uninitialized, not Ready. Without a reset/reopen latch, that fully retired
attempt can initialize again on the same owner, with a fresh bounded attempt.
A Boot observed before poisoned-write cleanup may still leave ResetRequired;
only the actor's eligible subsequent Boot/state transition permits writes.

If the transport closes after initialization/possible writes, retain a reset
latch across reopen attempts. A reopened transport only monitors until a Boot
is actually observed; then initialize. Ordinary open failure before a descriptor
or write does not create this latch. A parse/interference/write-poison condition
on an existing descriptor remains on that descriptor awaiting Boot.

Reopen must exclude buffered pre-open Boot packets too. Before accepting reset
evidence, obtain a no-write receive boundary through Transactions: a crate-private
wrapper around the existing monitor fence, holding its exclusive operation permit
and requiring Uninitialized. Save its minimum eligible sequence; only a Boot at
or after that boundary plus the actor's Uninitialized state may clear the reopen
latch. The monitor fence drains queued kernel bytes and excludes a partial line
already in progress. It does not expose/rearm the raw monitor or authorize a
write in ResetRequired. Test complete and split buffered Boot packets explicitly.
This boundary excludes covered readable bytes, not data delayed upstream or a
timestamped physical reboot; ATX carries no such identity. Do not claim stronger
reset attribution or weaken the P4 crash/reset-evidence prerequisite.

Initial healthy startup initializes via Version and reads bus-status snapshots
for configured enabled buses (bus zero if none). Use one original setup deadline,
not a fresh timeout per bus. Read-only health polling is paced and uses the same
Transactions owner. Poll failure obeys its Late/reset state rather than blindly
reconnecting. Proactive D snapshots may update health without being an ACK.
Bus power faults are bus facts; do not call a responding HAT disconnected merely
because a bus reports no power. No DALI fixture frame is sent in this slice.

**Verify before enabling fixture traffic in P4:** preserve unresolved transport
ambiguity across a process crash/startup as well. A fresh object/Version cannot
prove a previous process left no HAT work. Freeze a durable unclean-session or
equivalent reset-evidence boundary in the daemon/capability integration before
exposing mutating DALI Send operations. This slice's public service surface sends
only local HAT version/status queries; it does not claim that wider guarantee.

Unsolicited traffic stays in the existing bounded monitor stream. Drain it for
health/diagnostics without emitting decoded input actions yet. Lag is explicit,
invalidates related health certainty and requires resynchronization. P4/P5 must
still apply the already-recorded receive-sequence cutover for input generations;
raw packets must never be stamped with a replacement mapping after decoding.

## Implementation and verification record

Implemented the owned lifecycle component, optional resource-free UART builder,
raw health snapshots, runtime blocking opener, receive-boundary wrapper and joint
cleanup. Two sequential source reviewers approved after reproduced fixes for a
quiet retry losing its timer, simultaneous hardware events hiding a completed
helper panic, and fresh Boot discarding an already-completed receive boundary.
Helpers carry explicit kinds so Boot invalidates query observations while the
no-write boundary remains eligible for normal completion/minimum evaluation.
Connecting and completed Closed facts are published explicitly.

The final restored gate passed 215 native tests, scoped strict Clippy, armv7
library/v2/emulator compilation and changed-file formatting/diff checks. Eight
declared guard-removal controls each failed at the intended assertion and were
restored by the runner. Tests include real PTYs, independent emulator boot/power
observations, metadata during unanswered setup, actual descriptor close and a
blocked opener preventing a clean managed stop. Reviews are source-only and
same-family. The physical/crash-boundary limitations above remain unchanged.
